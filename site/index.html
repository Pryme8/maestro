Maestro shows everything running on your computer, shuts down whatever the task in hand does not need, and gives you one place to watch and direct the AI agents doing the work.

THE IDEA

Your desktop assumes you are doing the work. Increasingly, you are not.

Task Manager, Settings and the file explorer were built for a person clicking through windows. When agents do most of the work, the machine should be organised around them: its resources given to the task in hand, its state visible at a glance, and its controls built for directing agents instead of launching apps.

Maestro is that environment. It runs on top of the operating system you already have and takes over the interfaces you use to see and manage it. It is one executable with no browser engine inside, because a tool whose job is to free the machine should not bring one with it.

WHAT WORKS TODAY

Everything on the machine, and a hand on all of it.

Each feature below says how far it has been tested. That line is taken from the project's own status page.

BASE

Your machine as a base you can read at a glance

Processor, memory, disks and network every second. Every process grouped by program, with the file on disk behind it and what started it. Draw the same data four ways: tiles, a heat map, a tree of what started what, and a map.

Each process is sorted in plain words as critical to the system, part of the system, a background service or an app. A program that has touched neither processor nor disk for 15 minutes is counted as cold, and a critical system name running from outside the system folders is flagged, because that is a common disguise.

Tested Seen on screen on Windows with real data. The cold count has unit tests; the stale flags have not yet been seen on screen.

FOCUS

Clear the machine for the task

Pick the program that matters. Maestro lists what could be paused and pauses nothing until you confirm. The task, what started it and what it started are always left running. Save the set as a profile and use it again with one click.

Paused programs lose nothing and resume where they stopped. Everything paused is written to disk first and resumed when Maestro closes, so nothing is ever left frozen.

Tested Pause, resume, end and the locks were run on Windows and Linux. The buttons have been seen but not yet clicked through by a person.

NETWORK

Who every program is talking to

Every connection sits under the program that opened it, with the name and owner behind each address, marked as this computer, your network or the internet. Every listening port is shown with whether other computers can reach it.

Tested Seen with real data on Windows. Blocking one program at the firewall is written and has not been run.

CREW

Your agents, recognised by themselves

Claude Code, Cursor, Codex, Copilot, Gemini CLI, Ollama and others are found among the running programs with no setup. The shells and scripts an agent starts are counted with it, so the processor and memory shown are what it is really using.

Tested Run on a machine with Claude Code, the Claude app, Copilot and Ollama. The rules for the other agents are untested.

LEDGER

Honest accounting of cost and quota

Agents that report usage show their tokens and cost for today, 7 days and 30 days. Set a daily budget per agent. List your AI accounts and the advisor proposes the cheapest route for a task, with the cost of the handoff counted in.

Subscription figures are labelled as estimates, because vendors do not publish them exactly. Maestro says so instead of guessing.

Tested The receiver was tested with a sample report, not yet a real agent. The advisor has unit tests and was run from the command line.

CONTROL

Every action can be undone or asks first

An action log runs along the bottom of the window with an undo on everything that can be undone. Ending a program takes a second click. Processes the system needs are locked, from the window and the command line alike.

Tested The locks and resume-on-close were run against a throwaway process.

LIVE

Watch an agent think. Decide what it may do.

The Live page starts Claude Code sessions, shows every step as it happens, and puts each risky one in front of you before it runs.

01

A live map of every tool call

What was asked, what the agent said, each tool call with the command, file or search in it, and what came back. The most recent is brightest. A failed call turns its tool red.

02

Allow or refuse each step

A session started from Maestro asks before every step that needs permission. You see the tool, the exact command or file and why it has to ask. No answer means no. A closed window means no.

03

A safe copy with rollback

By default the session works in a separate copy of your repository on its own branch, with a snapshot taken first. See what it changed, keep it as a commit, or roll the whole thing back.

04

Work and personal, kept apart

Keep several Claude Code sign-ins, each in a folder of its own, and pick the account and the model per session. Two accounts never share a sign-in, a setting or a history file.

Tested A person drove a full session from the window on Windows: start, allow an edit, refuse a command, pause, resume and stop. A second real account has not been signed in yet, and Live works with Claude Code only today.

TRUST

It runs with your rights. So its rules are written down.

Maestro can pause and end programs and sits beside your AI tools' sign-ins. These are the promises the code keeps today. Five of the eight are checked by tests on every pull request.

  1. It does not read sign-ins. It points a tool at its folder and never opens what is inside. held by a test
  2. It does not keep keys. It stores the name of a variable. The key is handed to the tool and never written, logged or shown.
  3. It sends nothing off your computer. No server of its own, no telemetry, no update check. held by a test
  4. Nothing listens where other computers can reach it. held by a test
  5. It starts only programs on a short, written list and does not build command lines from outside text. held by a test
  6. Administrator rights go through your system's own prompt, every time. It never keeps raised rights.
  7. An agent is refused unless you allow it.
  8. It builds only from the public crate registry, from fixed versions, with no build script. held by a test

The only thing that reaches a network by itself is a name lookup for addresses on the Network page. It goes to the DNS server your system already uses and can be switched off. This website follows the same idea: it loads no trackers, fonts or scripts from anywhere else. Read the rules in full in SECURITY.md.

STRAIGHT TALK

What it will not claim

  • Clearing the machine frees memory and processor for local work such as builds and local models. It does not make a cloud-hosted model answer faster.
  • It shows who a program talks to, not the contents of encrypted traffic.
  • It is not an antivirus.
  • It cannot measure answer quality. “Best route” means cheapest within your rules.
  • A safe copy protects your files, not your machine. That is what approving each step is for.

GET IT

Three lines to a running base.

Built from source for now. You need a Rust toolchain, version 1.84 or newer. Linux needs a few packages first: see the install guide.

terminal
$ git clone https://github.com/Pryme8/maestro.git
$ cd maestro
$ cargo run --release

It also works without its window:

$ cargo run -- --agents              # the AI agents found running
$ cargo run -- --connections         # who each program is connected to
$ cargo run -- --watch               # what your Claude Code sessions are doing
$ cargo run -- --focus-plan code.exe # what clearing the machine for it would pause
